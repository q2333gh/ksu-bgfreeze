# UI/UX 计划（v0.3）

## 目标

在**不改系统其它行为**的前提下，给黑名单一个可点的管理面：

- 应用列表（名称 + 包名）
- 应用图标
- 勾选 / 取消勾选
- **应用**按钮：写入黑名单并立刻对守护进程生效

入口：**KernelSU 管理器 → 本模块 → WebUI**（不另装 App）。

## 信息架构（一页做完）

```
┌─────────────────────────────────────┐
│ 后台冻结 · 黑名单                    │
├─────────────────────────────────────┤
│ [搜索…]                              │
├─────────────────────────────────────┤
│ 正在冻结  N                          │
│ ☑ 🖼 应用宝  com…  [冻结]           │  ← 黑名单专区（更醒目）
├─────────────────────────────────────┤
│ 其它应用  M（紧凑行）                 │
│ ☐ 🖼 某某 App                        │
│ ☐ 🖼 …                              │
├─────────────────────────────────────┤
│ 黑名单 N           [ 应用 ]          │
└─────────────────────────────────────┘
```

## 交互细则

| 元素 | 行为 |
|------|------|
| 列表行 | 整行可点，切换勾选；显示图标、应用名、包名 |
| 搜索框 | 即时过滤名称/包名 |
| 勾选状态 | 打开页面时从 `blacklist.txt` 回填 |
| **应用** | 把当前勾选写回 `/data/adb/ksu-bgfreeze/blacklist.txt`，重启守护进程；Toast「已应用」 |
| 空选 + 应用 | 写入空名单 = 全部不冻（符合 POC 语义） |
| 未改就点应用 | 仍可写盘（简单、可预期） |

## 不做（保持迷你）

- 无独立桌面 App
- 无多页设置、无模式切换、无白名单页
- 无推送/通知栏常驻
- 不改系统设置里的应用详情页

## 图标策略（POC）

1. 优先：从 APK 里抽 `ic_launcher` PNG → base64 给 WebUI  
2. 失败：用应用名首字色块头像（仍保持「有图标位」的列表节奏）
3. 列表先渲染文字；图标队列并发 ≤2，避免打开时打爆 `ksu.exec`

## 列表性能

- **慢因（已修）**：旧实现对每个第三方包各跑一次 `dumpsys package`，几十个应用即可到 ~20s。
- **现策略**：整机 `dumpsys package` 一次写入 `labels.cache`（24h 内复用），再与 `pm list packages -3` 合并。

## 与冻结逻辑的关系

WebUI **只改黑名单文件**；冻结由守护进程完成。冻结期间每个 poll 会对同 uid **补发 SIGSTOP**（打保活子进程），名单外零干预。
